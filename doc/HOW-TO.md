# How-to AHK v2 (knowledge base)

Collection of pitfalls, mistakes and solutions encountered while implementing in AutoHotkey v2. Meant as a help for agents and developers who work on the code after us.

If you notice a difficulty or a mistake of your own, record it here (see `AGENTS.md`, rule 9).

## Entry format

```markdown
### <short title>

- **Problem:** What went wrong or what was difficult.
- **Wrong:** The faulty approach or code (brief).
- **Right:** The working solution (brief, with a code example if needed).
- **Status:** verified (tested/read) | assumed | not checked
- **Source:** Doc link or file where it occurred (optional).
```

Append new entries at the end of the matching category. Correct or delete outdated entries, do not duplicate them.

## Syntax and language

### A lambda cannot contain `throw`

- **Problem:** A test wanted to throw an error from a lambda. The script aborted while loading.
- **Wrong:** `TestRun.Case("x", () => throw ValueError("boom"))`
- **Right:** `throw` is a statement, not an expression. Use a named function that throws, and pass that function.
- **Status:** verified (editor diagnostic and load error in `tests/ahk/selfcheck.test.ahk`)

### FileAppend writes a BOM for a new file; strip the BOM when reading

- **Problem:** Files written with `"UTF-8"` start with a UTF-8 BOM. A Python reader using `utf-8` gets `﻿` in front of the first JSON object. v1 variable files also start with a BOM, which breaks `Json.Parse`.
- **Wrong:** `FileAppend(line, path, "UTF-8")` and reading with `encoding="utf-8"`.
- **Right:** A BOM is only written with `"UTF-8"` or `"UTF-16"`, and only when the file is newly created. Python reads such files with `utf-8-sig`. For output without BOM use `"UTF-8-RAW"`. When reading text that may start with a BOM, remove `Chr(0xFEFF)` at the start (see `AtomicFile.ReadText`).
- **Status:** verified (BOM seen in output; `UTF-8-RAW` output without BOM in `tests/test_json_flows.py`; BOM strip in `AtomicFile.ReadText`). Whether AHK itself strips the BOM on read with `"UTF-8"` was not checked.
- **Source:** `src/storage/AtomicFile.ahk`

### `#Include` is relative to the including file

- **Problem:** Test scripts include `lib\Assert.ahk`. It was unclear which directory the path refers to.
- **Right:** A relative `#Include` path refers to the directory of the file that contains the `#Include`. `SetWorkingDir` has no effect on it, because includes are processed at load time. For paths in files generated by Python, use absolute paths.
- **Status:** verified (tests with scripts in the data directory and in `tests/ahk/`)
- **Source:** https://www.autohotkey.com/docs/v2/lib/_Include.htm

### A static method used as a callback shifts the parameters

- **Problem:** `Log.Configure(Log.Memory)` with `static Memory(level, source, text, flowId)` received the second argument as `level`. A sink called as `this.sink(...)` received the object as an extra first argument. Both errors were silently swallowed, which made the cause hard to see.
- **Wrong:** Passing a static method as a sink, or calling `this.sink(level, ...)` where `sink` is a method.
- **Right:** Store the callback as a function property, `static Memory := (level, source, text, flowId := "") => ...`. Call it through a local copy: `sink := this.sink`, then `sink(level, ...)`. The function then receives exactly the arguments passed.
- **Status:** verified (`tests/ahk/core_log.test.ahk`, cases "custom sink function" and "sink receives level, source, text and flowId")
- **Source:** `src/core/Log.ahk`

### Backslash is not an escape character in AHK v2

- **Problem:** When writing JSON test texts, the length did not match, because `"\\"` yields two backslashes.
- **Right:** `"\"` is one backslash, `"\\"` is two. The escape character is the backtick: `` `n ``, `` `t ``, `` `r ``. Inside `"..."` a quotation mark is `""`; inside `'...'` it is a plain `"`. Write JSON text with escapes in single quotes: `'"é"'`.
- **Status:** verified (`tests/ahk/json.test.ahk`, cases for control characters and escapes)

### `<` compares strings numerically, `Sort` sorts only text

- **Problem:** `"a" < "B"` opened the dialog "Expected a Number but got a String". `Sort(array)` opened "Parameter #1 of Sort requires a String".
- **Wrong:** `if (a < b)` for text order. `Sort(arr)` with an array.
- **Right:** Compare text order with `Ord()` of the characters (see `Json.Less` in `src/core/Json.ahk`). `Sort` works only on text with delimiters, not on arrays.
- **Status:** verified (observed in experiments; `Json.SortedKeys` in the tests)

### `=` and `!=` compare strings case-insensitively

- **Problem:** A literal check should not accept `True` as `true`.
- **Wrong:** `SubStr(text, pos, 4) != "true"`.
- **Right:** `!==` (and `==`) compare case-sensitively. `Json.ParseLiteral` uses `!==`.
- **Status:** verified for `!==` (test "invalid literal is rejected" with `[True]`). `!=` itself was not tested separately; behavior taken from the documentation.

### Float as text: precision and form

- **Problem:** The standard conversion is unsuitable for JSON: precision is lost, and `1.0` becomes `1`, which reads back as an integer.
- **Wrong:** `"" f` or `String(f)` for JSON output.
- **Right:** `Format("{:.15g}", f)`; if `Float(s) != f`, use `Format("{:.17g}", f)`. If neither `.` nor `e` is present, append `.0`. `Float("1e400")` returns `inf`, which must be rejected beforehand (`f - f != 0`).
- **Status:** verified (`Format` outputs such as `1/3` giving `0.33333333333333331` and `1.0` giving `1`; precision tests). The default float-to-text conversion was not checked.

### Nested class with a static singleton

- **Problem:** `Json.Null` should be a singleton of its own class, without a second class in the same file.
- **Right:** `class Json { class NullValue {} static Null := Json.NullValue() }`. `Type()` returns `Json.NullValue`. The nested class must come before the static line.
- **Status:** verified (`tests/ahk/json.test.ahk`, case "Json.Null is a singleton")

### Performance: calls per character are expensive

- **Problem:** A parser using `SubStr` and a property access per character needed 2.8 s for 10,000 messages of 364 characters each. Strings with many escapes are also expensive: a 92,808-character flow text took 161 ms in `Message.Parse` and 143 ms in `Json.Parse`.
- **Right:** Read runs of text with one `RegExMatch` call, read character codes via `NumGet` from a UTF-16 buffer, and skip whitespace without regex when none follows. This brought parsing to about 1.5 s and writing to 0.6 s for the test workload; the goal "under 1 s" was not reached. For large flows, send the payload as an object instead of a string, so it is parsed only once (not implemented yet).
- **Status:** verified (measured, values vary per run)
- **Source:** `src/core/Json.ahk`

### Reserved word `loop` must not be used as a variable name

- **Problem:** A test variable named `loop` produced "The following reserved word 'loop' must not be used as a variable name", plus follow-up errors such as "Missing operand".
- **Wrong:** `loop := inst.Threads["t1"]`
- **Right:** Choose another name (`loopThread`). The word inside a string (`"type":"loop"`) is harmless. Read the editor diagnostics before the first run.
- **Status:** verified (editor diagnostic in `tests/ahk/engine_scheduler.test.ahk`)

### Truth values are the integers 1 and 0

- **Problem:** A method that returns `true` or `false` returns an integer. `Assert.Equal(x, false)` therefore compares integers, and the message shows "expected 0 (Integer)".
- **Right:** For return values such as `TryTransition`, use `Assert.Equal(ok, false)` or `Assert.True(ok)`. For values that go over the wire, see "`Json.False` is true in AHK".
- **Status:** verified (`tests/ahk/engine_states.test.ahk`)

### Local variable with the name of a class shadows the class

- **Problem:** Identifiers in AHK v2 are not case-sensitive. A local variable `role := ...` shadows the class `Role` in the whole function, and a later `Role.ConsoleFn(...)` fails with "This local variable has not been assigned a value". The same happened with `children`/`Children`, `log`/`Log` (a parameter) and `hub`/`Hub`. With the parameter `log`, the error showed up only as a hub log line "no handler for ...", because the dispatcher wraps handler exceptions.
- **Wrong:** `role := Role.Current`, `Log.Write(...)` in a function with a parameter `log`.
- **Right:** Name variables and parameters differently (`owner`, `doLog`, `theHub`, `kids`). Do not name a local like a class.
- **Status:** verified (each case reproduced; dialogs at start, green after renaming)
- **Source:** `src/AutoHotFlow.ahk`, `src/supervisor/DiagLog.ahk`

### Function in a property: calling with a dot passes the class as the first argument

- **Problem:** `Role.ConsoleFn("a0", "role", text)` (a function property with a lambda) opened the dialog "Expected a String but got a Class". The first parameter was the class `Role`, not the level.
- **Wrong:** `static ConsoleFn := (level, source, text) => ...` called as `Class.ConsoleFn(...)`.
- **Right:** Call the function through a static method (`Role.Console(...)`). Pass the property only as a value, e.g. `Log.Configure(Role.ConsoleFn)`.
- **Status:** verified (dialog at start, green afterwards). Why AHK passes the class was not looked up: assumed.
- **Source:** `src/core/Role.ahk`

### Field and method with the same name

- **Problem:** A class had a field and a method whose names differ only in capitalization (`_loaded` and `_Loaded()`). Access to the field failed with "Property is read-only", because identifiers are case-insensitive.
- **Right:** Name fields and methods so that they differ in more than capitalization. Before naming a method `_X()`, check whether a field `_x` already exists.
- **Status:** verified (role start failed with exit 2 and this message; green after renaming the field to `_flowsLoaded`). It came back in WI-0041 (`_failed` in `VarWriter` against the method `_Failed()`): the engine then ended with exit 2 "bad arguments: Property is read-only" before any other test could say why; see the entry "An error in a constructor of a role shows only as exit 2" below.
- **Source:** `src/engine/Engine.ahk`

### `Json.False` is true in AHK

- **Problem:** AHK v2 has no Bool type, and every object is true. `Json.True` and `Json.False` are objects, so that `Stringify` can write `true`/`false`. Therefore `if Json.False` is true. Keeping such a value in program state and checking it with `if` is a silent error.
- **Wrong:** `payload["ok"] := Json.False` and later `if (payload["ok"])`.
- **Right:** Use `Json.True`, `Json.False` or `Json.Bool(x)` only when building a message, right before sending. `Message.Serialize` converts `ok` on a copy. When forwarding a parsed payload, set the boolean fields again with `Json.Bool`: parsing yields `1`/`0`, so a report built from parsed replies would otherwise write `1` instead of `true`. In AHK tests compare with `value == Json.False`. Python tests check `is True` / `is False` (`tests/support/wirebool.py`).
- **Status:** verified (`tests/ahk/json.test.ahk`, `tests/ahk/message.test.ahk`; the report case was found by the Python guard in `tests/conftest.py`)
- **Source:** `src/core/Json.ahk`, `src/core/ipc/Message.ahk`, `doc/PROTOCOL.md` section 2

### `Round(x, 1)` returns a string

- **Problem:** A measured value with `Round(ms, 1)` ended up in a JSON file as `"14.1"`, and the Python test compared it with a number.
- **Right:** `Round(x, n)` with `n > 0` returns a `String`; `Round(x)` returns an `Integer`. For a number, write `Round(x, 1) + 0`.
- **Status:** verified (`Type(Round(3.14159, 1))` returns `String`)

### `===` does not exist; `ObjPtr("")` throws

- **Problem:** Comparing two objects for identity with `===` is a syntax error ("Missing operand"). `ObjPtr` on an empty value throws "Expected an object".
- **Wrong:** `if (a === b)`, `ObjPtr(this._conn)` when `_conn` is empty.
- **Right:** `IsObject(a) && ObjPtr(a) = ObjPtr(b)`. Check `IsObject` before `ObjPtr`. The same identity check tells whether a connection is still the current one (`ObjPtr(c) != ObjPtr(this._conn)` in `src/core/ipc/Peer.ahk`).
- **Status:** verified (syntax error at load time; the identity check is used in the peer teardown path)
- **Source:** `src/engine/Executor.ahk` (`_DispatchWorker`)

### Class used from a file that is not included: load-time dialog

- **Problem:** `src/manager/StubManager.ahk` called `StubGui(this)`, but `StubGui.ahk` was not included. AHK reports this at load time as a warning dialog ("This local variable appears to never be assigned a value. Specifically: StubGui"). Without a guard the process hangs.
- **Right:** Include every file whose classes a file uses. Dialogs of role processes are stored under `%TEMP%\ahf_dialogs\` (text and PNG).
- **Status:** verified (dialog captured at role start; green after adding the `#Include`)
- **Source:** `src/manager/StubManager.ahk`

### Do not override built-in AHK v2 class names

- **Problem:** `class TimeoutError extends AhfError` reports "This class declaration conflicts with an existing Class" at load time and blocks with a dialog.
- **Right:** Use your own names with a prefix (`AhfTimeoutError`). Built-in names include `Error`, `TimeoutError`, `ValueError`, `TypeError`, `OSError`, `MemberError`, `PropertyError`, `MethodError`, `IndexError`, `KeyError`, `UnsetError`, `TargetError`, `MemoryError`, `ZeroDivisionError`.
- **Status:** verified for `TimeoutError`; the rest of the list is from the documentation, not checked individually.

### Code at file level runs at load time, before `AhfMain` and before any `OnError`

- **Problem:** Element files call `ElementRegistry.Register(...)` at file level. This runs at load time, before the entry point. An error there (duplicate class, invalid option) showed an error dialog at start. `/ErrorStdOut` covers load errors only, not run-time errors in this code.
- **Right:** `OnError(Handler)` as the first executable statement of the entry point, before the `#Include` lines (functions are known beforehand). The handler writes to stderr and calls `ExitApp(1)`. Before the role starts, remove it with `OnError(Handler, 0)`, so that the role's own handler is the only one. The reason (several handlers run one after another, and a handler that returns 1 stops the later ones) is assumed from the documentation and was not reproduced.
- **Status:** behavior verified (`tests/integration/test_entry.py::test_error_while_loading_files_shows_no_dialog_and_ends_with_exit_1`: before exit 97, afterwards exit 1 with a message on stderr). The order of handlers: assumed.
- **Source:** `src/AutoHotFlow.ahk`, `tests/integration/helpers/RegisterFailure.ahk`

### 32-bit interpreter: check `A_PtrSize` before anything else

- **Problem:** Starting the entry point with `AutoHotkey32.exe` ran a supervisor that then failed in `DllCall` structures, because pointer sizes differ.
- **Right:** `if (A_PtrSize != 8)` as the first statement, before the `#Include` lines: message on stderr, `ExitApp(2)`.
- **Status:** verified (red before: timeout; green afterwards: exit 2 without dialog)
- **Source:** `src/AutoHotFlow.ahk`, `tests/integration/test_entry.py`

### A closure without a captured variable is always the same function object

- **Problem:** `loop 21 { SetTimer(() => Werfe(), -10 * A_Index) }` started only **one** timer. `SetTimer` identifies a timer by its function object, and all closures without captured variables are the same object: each call only reset the timer (1 error seen, 21 expected).
- **Right:** Make each closure capture something of its own, e.g. `static MakeFn(n) => () => Werfe(n)` and `SetTimer(MakeFn(A_Index), -10 * A_Index)`.
- **Status:** verified (`tests/fault/test_diagnose.py::test_too_many_unhandled_errors_end_the_role_with_exit_6`)
- **Source:** `tests/integration/helpers/EchoRole.ahk`

### A space before `;` inside a string literal starts a comment

- **Problem:** In the AHK source, `"a ; b"` or `'x ; y'` is cut at the `;` and the file fails to load with `Missing """`.
- **Wrong:** `Assert.Equal(S("x := 1 ; c"), ...)` in a test file.
- **Right:** Write the semicolon escaped: ``"x := 1 `; c"``. A `;` without whitespace in front (`"a;b"`) is fine.
- **Status:** verified
- **Source:** `tests/ahk/expr_*.test.ahk`

### Call stack overflow ends the whole process

- **Problem:** A function recursion deeper than about 2000 calls (between 1500 and 3000 measured) is a critical error: AutoHotkey shows a dialog and exits. It cannot be caught with `try`.
- **Wrong:** Recursive descent without a depth limit on input from users.
- **Right:** Count the nesting and report an error before the limit (`ExprParser.MAX_NEST`, `ExprNode.MAX_DEPTH`). A parser frame costs about 12 calls per nesting level.
- **Status:** verified (`F(n)` recursion test with `ahkrun.py`)
- **Source:** `src/expr/ExprParser.ahk`

### PCRE in AHK: characters above U+FFFF and a start position inside a surrogate pair

- **Problem:** `[\x{80}-\x{FFFF}]` does not match an emoji (one code point above U+FFFF, two UTF-16 units). `RegExMatch` with a start position in the middle of a surrogate pair stops with `PCRE execution error`.
- **Right:** Use `\x{10FFFF}` as the upper bound. When stepping over "one character" behind an escape character, take two units if the first one is in D800 to DBFF. Found by a random-input test.
- **Status:** verified
- **Source:** `src/expr/ExprTokenizer.ahk`, test `random input never throws and always gives consistent results`

### `Integer("12345678901234567890")` wraps around

- **Problem:** A decimal text beyond 63 bits does not throw; it returns a wrapped negative number (`-6101065172474983726`). `Integer("0xFFFFFFFFFFFFFFFFF")` gives `-1`.
- **Right:** Check the digit count (and compare to `"9223372036854775807"`) before converting; use `Float()` or report an error.
- **Status:** verified
- **Source:** `src/expr/ExprTokenizer.ahk`

### `MinInt // -1` and `Mod(MinInt, -1)` end the whole process

- **Problem:** `(-9223372036854775807-1) // -1` and `Mod(-9223372036854775807-1, -1)` do not throw. AutoHotkey shows "Critical Error: System exception 0xC0000095" (integer division overflow) and ends the process; a `try`/`catch` does not help. An expression language that passes user numbers to `//`, `Mod` or an integer division check would be killed by one text.
- **Wrong:** `try result := a // b catch ...` (also `Mod(a, b)` for the exactness test of `/`).
- **Right:** Check before the calculation: if both operands are integers, the divisor is -1 and the dividend is the smallest Integer, refuse (the evaluator throws a `ValueError` that it catches itself) or take another way (`-a`). `MinInt / -1` with the `/` operator is fine (gives a Float), and so are `MinInt // 1`, `-MinInt` and `MinInt * -1` (they wrap around).
- **Status:** verified (the cases above run with `ahkrun.py`; the dialog was caught)
- **Source:** `src/expr/ExprEvaluator.ahk` (`FloorDivide`, `Divide`), `src/expr/ExprFunctions.ahk` (`_Mod`)

### A property and a method that differ only in case are the same name

- **Problem:** `static _table := ""` and `static _Table() {...}` in one class: the load of the script fails with "Property is read-only. Specifically: _table" at the initializer, because the method of the same (case-insensitive) name replaced the property.
- **Wrong:** a field `_table` and a method `_Table()` in one class.
- **Right:** Names of members are case-insensitive; give the field and the accessor different names (`_entries` / `_Table()`).
- **Status:** verified
- **Source:** `src/expr/ExprFunctions.ahk`

### A semicolon after whitespace starts a comment even inside a string in the source

- **Problem:** `Assert.Equal(EvalCheck.Value("  ; comment"), "")` fails to load with `Missing """`: the text from ` ;` on was cut off as a comment.
- **Wrong:** `"  ; comment"` in a double-quoted string in a script file.
- **Right:** Build the text: `"  " Chr(59) " comment"` (or escape the semicolon with a backtick). A `;` directly behind the opening quote (`"; comment"`) is fine.
- **Status:** verified (load error and fix in `tests/ahk/expr_eval_vars.test.ahk`)

### Comparing two characters with `>=` or `<=` throws a TypeError

- **Problem:** `c >= "0" && c <= "9"` to test for a digit works for a digit and throws `TypeError` for a letter: `>=`, `<=`, `<` and `>` need numbers, or texts that look like numbers. This is the same rule that E0030 applies to flows. In the converter (`V1ExprConverter`) the whole conversion of a text ended in the harness with "Expected a Number but got a String".
- **Wrong:** `if (c >= "0" && c <= "9")`
- **Right:** `InStr("0123456789", c)` with `c != ""`, or `Ord(c)`. Equal (`=`) and `==` work on any texts.
- **Status:** verified
- **Source:** `src/expr/V1ExprConverter.ahk` (`_IsDigit`)

### A local variable has the name of a function or class: `lines`, `log`

- **Problem:** Names ignore case. A function `Lines(...)` of a test file and a local variable `lines := []` in another function are the same name; the call `Lines(...)` then fails with "has no method" or "not assigned a value". The same for `log := []` and the class `Log`: `Log.Configure(...)` was called on the Array.
- **Wrong:** `log := []` in a function that also uses `Log.Configure(...)`.
- **Right:** Other names for locals (`entries`, `output`). When a call says "This value of type Array has no method named Configure", look for a local with the name of the class.
- **Status:** verified
- **Source:** `tests/ahk/engine_flow_convert.test.ahk`

### `String(0.1)` is `0.10000000000000001`: a decimal literal rarely reads back as it was written

- **Problem:** AutoHotkey v2 writes a Float with up to 17 significant digits. `String(Number("3.14"))` is `3.1400000000000001`, `String(Number("1.10"))` is `1.1000000000000001`; only values that a double holds exactly (`1.5`, `0.25`, `100.25`) come back as written. A check "does the text form of the number equal its spelling" is therefore true for few decimals. v1 passed a number literal on as text, so `x := 3.14` in a v1 flow must not become `3.1400000000000001`: the converter writes such a literal as a string where the text form counts.
- **Right:** For the text of a decimal that the user typed, keep the string; for calculations the number is fine.
- **Status:** verified (`String(Number(t))` for 9 spellings; golden cases)
- **Source:** `src/expr/V1ExprConverter.ahk` (`_CheckLiteral`), E0032

### A backtick before an apostrophe in a single-quoted AHK string is an escape

- **Problem:** In a test source `'"a`' esc 'b"'` the `` `' `` is an escaped apostrophe, so the string does not end there and the file does not load ("Missing "'""). The same holds for a double-quoted string with `` `" ``. A backtick followed by a letter that is not an escape (`` `x ``) is silently dropped, so a test text meant to contain a backtick did not.
- **Wrong:** `'"a`' esc 'b"'`, `'"a`xb"'` to build texts with a backtick.
- **Right:** Build the text with `Chr(96)`, or write `~` in the source and replace it (`B(text) => StrReplace(text, "~", Chr(96))`).
- **Status:** verified
- **Source:** `tests/ahk/expr_v1convert.test.ahk`

### `StrSplit("", ".")` gives an empty Array, not `[""]`

- **Problem:** The variable access split a name at the dots and took `parts[1]` as the root. For the empty name the harness failed with `IndexError: Invalid index`.
- **Wrong:** `parts := StrSplit(name, ".")` and then `parts[1]` without a check.
- **Right:** Check `parts.Length = 0` first. `StrSplit("a.", ".")` gives two parts (`"a"` and `""`).
- **Status:** verified (probe with `ahkrun.py`)
- **Source:** `src/engine/vars/VarAccess.ahk` (`_Find`)

### `IsNumber` of AutoHotkey v2 is not v1 `is number`: `"1e3"`

- **Problem:** The number checks of the parameter evaluation port v1 `if x is number` / `is integer`. It was unclear whether `IsNumber`/`IsInteger` give the same answers.
- **Right:** For 14 texts (`"5"`, `" 5 "`, `"5."`, `".5"`, `"0x10"`, `"1e3"`, `"abc"`, `"-3"`, `"+3"`, `"1.5"`, `"007"`, `"-abc"`, `"1,5"`, `"5 x"`) the answers are the same, spaces around a number included, except `"1e3"`: a number in v2 (`IsFloat`), not in v1. A Float such as `4.0` is no integer (`IsInteger(4.0)` is 0). v1 `x >= 1` with a text that is not a number compares alphabetically (`"abc" >= 1` is true, `"-abc" >= 1` false); `StrCompare(text, "1") >= 0` gives the same.
- **Status:** verified (probe scripts in the v1 interpreter and in v2 with `ahkrun.py`); MIGRATION M-0048
- **Source:** `src/elements/base/ParamEvaluator.ahk` (`V1AtLeast`)

### A nested class has no global name: inside an element class use `this`

- **Problem:** Since WI-0047 an element class is nested in the class of its package (`class Default { class Action_Sleep ... }`). A static method that called its own class by name (`Action_Sleep.ToMs(params)`, `Action_TestSetVar.Plain(item)`) failed at run time with "This local variable has not been assigned a value" (`UnsetError`); with `#Warn` the load already warned "This local variable appears to never be assigned a value. Specifically: Action_A".
- **Wrong:** `static Run(ctx, params) => Action_Sleep.ToMs(params)` inside the package class.
- **Right:** `this.ToMs(params)`: in a static method `this` is the class (also inside a fat-arrow lambda of the method). From outside, the full name: `Default.Action_Sleep`. `tools/gen_element_includes.py` refuses a class file that names its own class.
- **Status:** verified (probe script, 2026-10-15; test case in `tests/test_element_includes.py`)
- **Source:** `src/elements/Default/Actions/Action_Sleep.ahk`

### `#Include` inside a class body: a file is included only once, so include it before the class

- **Problem:** The package class includes the element files in its body. An element file itself includes `AhfElement.ahk` and shared code. An `#Include` of a file that was not included before would put that file into the class body: a class there becomes a nested class (`Default.AhfElement`), code at file level a load error.
- **Right:** Include every file that the element files include before the class (the generator does this), with the same file: AutoHotkey includes a file only once (resolved path), so the `#Include` lines inside the body are then skipped, whatever the relative spelling. `#Requires` inside the body is harmless. `#IncludeAgain` would include it again inside the body; the generator refuses it.
- **Status:** verified (probe script with `#Include ..\..\base\Base.ahk` inside a class body after the same file at file level, 2026-10-15)
- **Source:** `tools/gen_element_includes.py`, `src/elements/Default/_includes_engine.ahk`

### A package class is a global name: a local variable `default` shadows `Default`

- **Problem:** The package `Default` is the global class `Default`. A local variable or parameter `default` (common in code: `Get(key, default := "")`) is the same identifier (not case-sensitive). In that function `Default.Action_Sleep` then reads the local variable. With `#Warn All` an assigned local `default` gives the warning "This local variable has the same name as a global variable" (a parameter does not).

## Objects, Maps, Arrays

### Map with `CaseSense "Off"` keeps the spelling of the first insertion

- **Problem:** Are key spellings preserved when enumerating a case-insensitive Map?
- **Right:** Yes. The first insertion fixes the spelling; a later insertion in another spelling only replaces the value. Enumeration is sorted (`apple`, `mango`, `zebra`). Two keys that differ only in spelling become one, which `Json.Parse` rejects.
- **Status:** verified (`tests/ahk/json.test.ahk`). The sorted enumeration is observed, not documented.

### Copy keys into an array before deleting from a Map

- **Problem:** When an instance stops, threads are removed from a `Map` while iterating over it.
- **Right:** First copy the keys into an array, then iterate over the array (`Instance.Stop`).
- **Status:** not checked (whether deleting during a `for` loop over a Map works was not tested; the copy avoids the question)
- **Source:** `src/engine/core/Instance.ahk`

### Static method `Name()` shadows the `.Name` property of a class

- **Problem:** The registry read the class ID from `cls.Name`. For element classes this returns a function (`Func`), because `static Name()` shadows the built-in property.
- **Wrong:** `id := cls.Name` for classes with `static Name() => ...`.
- **Right:** Read the class ID from an instance: `Type(cls())` returns `Action_Sleep`. Elements have no constructor, so the call is cheap. See `ElementRegistry.IdOf`.
- **Status:** verified (probe: `cls.Name` gives `Func`, `Type(cls())` gives the class name; `tests/ahk/element_registry.test.ahk`)
- **Source:** `src/elements/base/ElementRegistry.ahk`

### `static __New()` sets the key spelling of a static Map

- **Problem:** A `static` Map should find keys regardless of case. `CaseSense` cannot be set in the class line.
- **Right:** `static __New() { this.classes.CaseSense := "Off" }` runs when the class is loaded, before first use. Afterwards `Has("TRIGGER_MANUAL")` finds `Trigger_Manual`.
- **Status:** verified (probe; `tests/ahk/element_registry.test.ahk`, case "lookup is case-insensitive")
- **Source:** `src/elements/base/ElementRegistry.ahk`

### Callback with state: `ObjBindMethod` instead of a lambda in a loop

- **Problem:** The engine sends one read request per flow file. Each callback needs the name and path of its file.
- **Wrong:** `for f in files { peer.Request(..., (res) => this._OnRead(st, f["name"], res)) }`. Lambdas capture variables by reference, so all callbacks see the last entry.
- **Right:** `peer.Request(..., ObjBindMethod(this, "_OnFlowRead", st, name, path), timeout)`. The bound arguments come before the caller's argument.
- **Status:** verified (`tests/integration/test_engine.py`, loading of two flow files and an error file)
- **Source:** `src/engine/Engine.ahk` (`_OnFlowList`)

### Parameter of an element as an object with property access

- **Problem:** `Action_Sleep` reads `params.Duration` (property access, as in v1), but the flow file delivers the parameters as a `Map`.
- **Wrong:** Passing the `Map` directly as `params`.
- **Right:** Build an object: `p := {}` and for each key `p.%k% := v`.
- **Status:** verified (Sleep with Duration 200 in `tests/integration/test_engine.py`). Whether a `Map` with `HasProp` would behave the same was not checked.
- **Source:** `src/engine/Executor.ahk` (`_Params`)

### Clone only after the change: the clone inherits it

- **Problem:** `Scheduler.Advance` cloned the thread for the second connection after the first thread had received the loop element and the loop stack push. The clone inherited the push (depth 1 instead of 0), and the second rollback of the stack threw.
- **Right:** Establish the state once (pop), then create all clones, and only afterwards give each target its own change.
- **Status:** verified (tests `Advance: branching into a loop pushes only the loop thread` and `Loop: two tail connections pop the loop stack once` were red before the fix)
- **Source:** `src/engine/core/Scheduler.ahk`

### A Map orders by keys, not by insertion: FIFO needs an array

- **Problem:** The instances were kept in a `Map` with keys `inst-<n>`. Enumeration is sorted by key, not by start time, so it cannot serve as the FIFO queue of the policy `wait`.
- **Right:** Use a dedicated queue: an `Array` per flow, `Push` at the end, `RemoveAt(1)` at the beginning.
- **Status:** sorting by key verified (documentation and code); that `inst-10` sorts before `inst-2` is assumed (not measured).
- **Source:** `src/engine/Executor.ahk` (`_waiting`)

### `Map.Delete` on a missing key throws

- **Problem:** An event handler called `this._earlyReady.Delete(name)` for a name that was never entered. `Map.Delete` throws `UnsetItemError` ("Item has no value"). The peer caught the error and logged it, so the crash of a worker had no effect and the element hung.
- **Wrong:** `m.Delete(key)` without a check when the key may be missing.
- **Right:** `if (m.Has(key)) m.Delete(key)`.
- **Status:** verified (`test_killed_worker_ends_its_element_with_worker_crashed_and_the_pool_has_a_replacement`, red with this log line, green after the fix)
- **Source:** `src/engine/WorkerBridge.ahk` (`OnProcessEvent`)

### A subclass method silently replaces a same-named base class method

- **Problem:** `Role` got a method `_CmdSnapshot` for `cmd.diag.snapshot`, but the engine already had a private method `_CmdSnapshot`. The subclass method replaced the base method without a warning, and the engine's call ran the wrong code.
- **Wrong:** Creating a private method in a base class with a short, obvious name that a subclass may already use.
- **Right:** Use a unique name (`_CmdDiagSnapshot`). Before adding a method to `Role`, search for the name in all roles (`grep -n "_Name(" src`). A test that asks every role (`tests/fault/test_snapshot.py`) finds such a case.
- **Status:** verified (red with `KeyError: 'snapshot'` for the engine; green after renaming)
- **Source:** `src/core/Role.ahk`

### `Json.Parse` returns `true` as 1, not as `Json.True`

- **Problem:** `Json.True` and `Json.False` are for writing. A parsed `true` is the Integer 1, so `value == Json.True` is false for a marker that was read from a file.
- **Right:** Compare a parsed truth value with `1` (and accept `"1"` and `"true"` where a file may have been edited by hand), as `FlowExprConvert.IsMarked` does. `Json.Stringify` writes `Json.True` as `true`.
- **Status:** verified (unit test `tests/ahk/engine_flow_convert.test.ahk`)
- **Source:** `src/engine/core/FlowExprConvert.ahk`

### A Map key `1` and `"1"` are two keys; Integer keys come before texts

- **Problem:** In v1 `list.1`, `list[1]` and `list["1"]` are the same member. In an AutoHotkey v2 `Map` the Integer `1` and the text `"1"` are different keys (`m["10"] := 1` then `m.Has(10)` is 0), even with `CaseSense "Off"`. A Float key is stored as its text (`1.5` becomes `"1.5"`).
- **Right:** Normalize keys when storing and looking up (`VarValues.NormKey`: a text of decimal digits becomes the Integer). A `Map` enumerates its Integer keys in ascending order first, then its text keys sorted (with `CaseSense "Off"` without case: `_` before `A` before `b`). That is the order of v1 objects, so no own sort is needed.
- **Status:** verified (probe with `ahkrun.py`: `-3, 2, 10, "1.5", "1x", "_", "A", "b", "Z"`; golden case `objects.dict.whole`)
- **Source:** `src/engine/vars/VarValues.ahk`

### A function stored in an object that it holds is a reference cycle

- **Problem:** The source of the parameter evaluation (`ExecContext.EvalSource`) needs a log function that knows the current parameter. The first version stored `ObjBindMethod(this, "_EvalLog", src)` in `src` itself: `src` holds the function, the function holds `src`, and both are never freed (one leak per `EvalParams` call).
- **Wrong:** `src.logFn := ObjBindMethod(this, "_EvalLog", src)` (the same with a closure that captures `src`).
- **Right:** Bind a small separate object that holds only the changing data (`at := {param: ""}`; `src.at := at`; `ObjBindMethod(this, "_EvalLog", at)`). `at` does not hold `src`, so there is no cycle. See also "Reference cycle via `ObjBindMethod(this, ...)` in a field".
- **Status:** assumed (seen in review before it ran; the leak itself was not measured)
- **Source:** `src/elements/base/ExecContext.ahk` (`EvalSource`)

### A static class method is not a callback (`OnError`, `SetTimer`)

- **Problem:** `OnError(TestRun.OnUnhandled)` with a static method aborted with "Invalid callback function" during init, and the script ended without a result file. `SetTimer(Role.Run, -1)` with a static method opened the same kind of dialog.

### A callback that throws does not abort the state machine

### `OnError` handler: return 1 keeps the process alive

- **Problem:** An error in a timer must not end a role, and the standard dialog must not appear.
- **Right:** The handler returns `1`: the error counts as handled, no dialog appears, and the process keeps running. The second parameter `mode` tells the kind of error: `"Return"`, `"Exit"` (how an error from a timer arrives) or `"ExitApp"`. `Role._OnUnexpected` counts errors and calls `ExitApp(6)` when the threshold is exceeded.

### Console output is best effort and must not block shutdown

- **Problem:** Role processes started by a supervisor have no usable stderr. `FileAppend(text, "**")` throws `OSError (6)` there. In `Role._Exit` the exception skipped `ExitApp`, so after a hard kill of the supervisor all children kept running.
- **Wrong:** Testing the orphan case only with a Python hub and a role started via `ahkrun.py`, where stderr is valid.
- **Right:** Wrap console writes in `try/catch`. Before every `ExitApp` in the shutdown path, call nothing that can throw, or catch it. Test the orphan case with the real supervisor.

## Processes, pipes, messages

### Pipe reads and writes in parallel only with overlapped I/O

- **Problem:** A Python client needs a read thread while the main thread writes. With a synchronous handle (`open(..., "r+b")`) Windows serializes the I/O, so a pending read blocks the write.
- **Right:** Open the pipe with `FILE_FLAG_OVERLAPPED`, with its own OVERLAPPED structure and event per direction. Serialize writes with a lock; run reads with a timeout via `WaitForSingleObject` and `CancelIoEx`.
- **Status:** verified (`tests/support/test_client_hub.py`, request and reply while the read thread runs). The synchronous case itself: assumed.
- **Source:** `tests/support/winpipe.py`

### `PostMessageW` with a NULL handle reports success

- **Problem:** A test expected `False` for `PostMessageW(0, ...)` (no window). The call returns `TRUE`.
- **Right:** For "window does not exist", use a real, destroyed window handle. Do not use the return value of `wake()` as an error check.
- **Status:** verified (failing test, then removed)

### Overlapped structure: fields with ctypes

- **Problem:** The field sizes of the `OVERLAPPED` structure must match, otherwise `hEvent` is read from the wrong offset.
- **Right:** `ctypes.Structure` with `c_size_t` for `Internal`/`InternalHigh`, `DWORD` for `Offset`/`OffsetHigh`, `HANDLE` for `hEvent`. Pass buffers as integers via `ctypes.addressof(...)`.
- **Status:** verified (tests pass, read and write buffers)
- **Source:** `tests/support/winpipe.py`

### AHK overlapped pipe I/O with DllCall (pattern that works)

- **Problem:** Server and client need non-blocking pipes in AHK v2, without threads.
- **Right:**
  - `OVERLAPPED` as `Buffer(32, 0)`, event from `CreateEventW` (manual reset, not signaled) at offset `2*A_PtrSize + 8`. Keep structure, buffer and event as members, never as locals.
  - Read: `ResetEvent`, then `ReadFile(h, buf, n, 0, ov)` (a `NULL` byte counter is allowed with overlapped I/O). Return 0 with `A_LastError = 997` is normal. Never check completion with `WaitForSingleObject` after a return of 0; use `GetOverlappedResult(h, ov, &n, 0)`: 0 with error `996` (`ERROR_IO_INCOMPLETE`) means "not yet", any other error means the end. This also applies when `ReadFile`/`WriteFile` returned `TRUE` immediately.
  - Other side gone: `109` (`ERROR_BROKEN_PIPE`) on read, `232` or `109` on write. A read of 0 bytes in byte mode is also the end.
  - Close: `CancelIoEx(h, 0)`, wait (bounded) for the pending operations, only then `CloseHandle` and free the buffers. Frames written before the close remain readable by the other side.
  - Server: one waiting instance per `PipeListener`. `ConnectNamedPipe` can return `535` (`ERROR_PIPE_CONNECTED`): treat it as connected. Create the next instance before handing over the connected one, so a client never sees "not found".
  - Client: `CreateFileW` with retry on `2` and `231`. To wait, use `DllCall("Sleep")` and `WaitNamedPipeW`: AHK's own `Sleep` processes messages and would run timers and wake-up calls in the middle of the connection setup.
- **Status:** verified (`tests/integration/test_pipe.py`, 26 tests, with a Python peer and an AHK peer). That AHK's `Sleep` processes messages is from the documentation and not measured separately.
- **Source:** `src/core/ipc/PipeConnection.ahk`, `src/core/ipc/PipeListener.ahk`

### The wake-up call covers writing only; a follow-up timer drains the queue

- **Problem:** The wake-up message (`WM_AHF_WAKE`) says "data written", not "data read". A pending overlapped write and a connection break produce no message, so draining large frames stalled at 250 ms per frame.
- **Right:** (1) If a connection still has frames queued, `SendFrame`/`Pump` schedules a follow-up pump with `SetTimer(fn, -1)`. (2) A fallback timer (250 ms) detects connection breaks and new clients. Measured: the end of a process is noticed after 42 to 98 ms; a new connection without a wake-up call is accepted within about 250 ms. Clients should send a wake-up call after connecting. For Python clients: median response 226 ms without the wake-up call, 1.4 ms with `PostMessage(WM_AHF_WAKE)` after each write (10 runs). A Python hub that does not wake the receiver adds 250 ms per message direction, so the test hub must wake too (`WakingHub` in `tests/integration/test_peer.py`).
- **Status:** verified (measurements in test runs). Behavior with many clients in the real hub was not checked.
- **Source:** `src/core/ipc/Wake.ahk`, `src/core/ipc/PipeConnection.ahk`, `tests/stress/stresskit.py`

### Re-entry: Pump, SendFrame and handlers interrupt each other

- **Problem:** AHK threads are interrupted after 15 ms of run time by timers and messages. An `OnFrame` handler that calls `SendFrame`, and an interrupting `Pump`, access the same queues. Also, the check of a state transition and the following action can be interrupted between two lines: a timer that interrupted between check and start started an element twice.
- **Right:** Per connection, guard flags (`_pumping`, `_writing`) with an "again" flag. Wrap check and set in `prev := Critical("On") ... Critical(prev)`, because two separate lines could be interrupted. `Critical("On")` returns the previous setting. Act on the result of a transition (`if (!thread.Dispatch()) return`) and keep check and state change in one `Critical` block. Catch and log handler errors, so the state machine is not left half-finished. Defer `OnClose` from `SendFrame` with `SetTimer(fn, -1)`.
- **Status:** verified for the connection function (12000 ping-pong runs without a lost wake-up; `Tick` test red with 2 starts, green with 1). The guards against a real interruption were not reproduced on demand: assumed.
- **Source:** `src/core/ipc/PipeConnection.ahk`, `src/engine/Executor.ahk` (`Tick`)

### Handler return: only an empty value counts as "no result"

- **Problem:** `Dispatcher.Invoke` treated every non-object return value as "no return", so a handler returning `"text"` got `ok:true`.
- **Wrong:** `if (!IsObject(result)) return Map("ok", true)`.
- **Right:** `if (!IsObject(result) && result == "")` gives `ok:true`. Any other non-Map return becomes an `internal` error.
- **Status:** verified (test "a handler returning a non-Map is an internal error" was red, then green; `tests/ahk/dispatcher.test.ahk`)
- **Source:** `src/core/ipc/Dispatcher.ahk`

### Connection setup without blocking: one attempt, retry via timer

- **Problem:** `PipeConnection.Connect(name, 3000)` waits up to 3 s with `Sleep` in the caller. A peer that waits for the hub at startup stalls its message path for that long.
- **Right:** `PipeConnection.Connect(name, 0)` makes exactly one attempt and throws at once. The peer retries via `SetTimer` with backoff (100 ms, 200, 400, ... at most 2 s) and reports `hub_unreachable` after 10 s.
- **Status:** verified (`test_hub_gone_for_longer_than_the_budget_calls_onclosed`, `test_reconnect_after_hub_restart_resubscribes_and_reports_ready_again`)
- **Source:** `src/core/ipc/Peer.ahk` (`_Attempt`, `_ScheduleRetry`)

### One timer per request, switched off on reply

- **Problem:** Every request needs a timeout, and AHK offers no count of active timers.
- **Right:** One `SetTimer(fn, -timeoutMs)` per request; on reply `SetTimer(fn, 0)`. Count open requests with `Peer.PendingCount` (must be 0 at the end).
- **Status:** verified (10,000 sequential requests: handle count constant at 163, 0.99 ms per request)
- **Source:** `tests/integration/test_peer.py::test_10000_sequential_requests_keep_pending_and_handles_flat`

### `sys.shutdown`: do not close the connection inside the frame handler

- **Problem:** `sys.shutdown` must send `sys.bye` and then end the process. Closing the peer inside the frame handler closes the connection while it is still processing the frame.
- **Right:** In the handler only set `SetTimer(Role.ByeFn, -1)`. The timer sends `sys.bye {clean:true}`, closes with `Peer.CloseWhenFlushed` (see "Close discards the send queue"), and calls `ExitApp(0)` in the callback.
- **Status:** verified (`test_shutdown_sends_bye_and_exits_0_within_one_second`: exit 0 about 240 ms after the command). A direct `Close` in the handler was not tried.
- **Source:** `src/core/Role.ahk` (`_OnShutdown`, `_FinishShutdown`)

### Orphan guard: measure the deadline in its own timer

- **Problem:** The peer retries the connection setup for up to 10 s, but a role must end after 3 s without hub, so it needs its own clock.
- **Right:** A timer (200 ms) reads `peer.status`. While it reads `reconnecting`, the timer records the time. After 3 s without `ready` it calls `ExitApp(4)`.
- **Status:** verified (`test_hub_gone_role_ends_within_orphan_budget_and_leaves_no_process`: end 3.25 s after the hub stopped, no process left). The start of the deadline is accurate to about 200 ms.
- **Source:** `src/core/Role.ahk` (`_Guard`)

### Events before a subscription are lost: subscribe first, then take a snapshot

- **Problem:** A client that subscribes after startup does not receive earlier `evt.process.*` events. Waiting for an event that came before the subscription waits forever.
- **Wrong:** Waiting for an event that was sent before `cmd.topic.subscribe`.
- **Right:** Subscribe first, then fetch the state as a snapshot (`cmd.process.list` at the supervisor, `cmd.engine.snapshot` at the engine); process events afterwards. A readiness event (`ready`) does not mean that the content is loaded: after `ready`, poll `cmd.engine.snapshot` until the flows appear.
- **Status:** verified (`tests/integration/test_supervisor.py`, `tests/stress/stresskit.py` `wait_flows`)
- **Source:** `doc/PROTOCOL.md` section 5a, `src/supervisor/Children.ahk` (`Snapshot`)

### `Hub.Request`: the message must carry the registered ID

- **Problem:** The reply must find its callback via `corr`, which is the ID of the request. If the message carries a different ID than the one stored, the callback never fires, and only the timer ends the request.
- **Wrong:** Generating the ID again after it was stored in the callback directory.
- **Right:** Generate the ID once, store the callback under it, and set the same ID in the message. Start the timer after sending and stop it on completion.
- **Status:** verified (`test_answer_to_a_hub_request_reaches_its_callback_once`). A wrong ID was not provoked on purpose.
- **Note on log timing:** the stderr lines of the supervisor appear batched, not in real time (about 2 s delay at a 500 ms deadline in one test). Check the order via the replies, not via log timestamps.
- **Source:** `src/supervisor/Hub.ahk` (`Request`, `_Finish`)

### Worker: reply first, start the element via timer

- **Problem:** `cmd.worker.run` should answer `ok` at once, while the element runs afterwards. If the handler runs the element, the reply waits as long as the element.
- **Wrong:** Running the element in the handler and then `return Map()`.
- **Right:** Store the job, set `SetTimer(this._startFn, -1)`, and let the handler reply. The same for the result of a cancel (`evt.worker.done` via timer -1), so that the reply to `cmd.worker.cancel` arrives before the event.
- **Status:** verified (`tests/integration/test_worker.py`, hub capture: `res.worker.cancel` before `evt.worker.done`)
- **Source:** `src/worker/Worker.ahk` (`_CmdRun`, `_StopCurrent`)

### `DllCall("Sleep")` in a loop: messages are handled between slices

- **Problem:** A worker waited in `DllCall("Sleep", 1000)` and answered `cmd.worker.cancel` only after up to one slice: 812 ms with 1000 ms slices, 29 ms with 100 ms slices.
- **Wrong:** Assuming a long wait is blind to messages. A single `DllCall` is indeed blind, but AHK handles messages between command lines.
- **Right:** Split long waits into short steps (100 ms). The latency is then the length of the longest step.
- **Status:** verified (measurement: cancel 812 ms vs. 29 ms). The cause (message check between lines) is assumed.

### `cmd` reply later: return `Deferred.Marker()` and reply with `Peer.Reply`

- **Problem:** Storage should run file operations in a queue, not in the message path. `Peer` replies to a `cmd.*` when the handler returns, so a later reply was not possible.
- **Wrong:** Writing the file synchronously in the handler and then replying: every other message, including `sys.ping`, waits for the full file time.
- **Right:** The handler returns `Deferred.Marker()` and enqueues the request. The reply is sent later with `peer.Reply(msg, payload)`. ### Atomic replace: `MoveFileExW` with flags, and flush before the rename

- **Problem:** v1 deletes the file and writes it anew (`FileDelete` + `FileAppend`); a crash in between loses the file. Also, the temp file was only closed before the rename, so after a power failure the rename could reach the disk before the data.

### Log lines are lost when another process has the file open (sharing violation)

- **Problem:** Under load, log lines went missing as soon as another process (test reader, editor, virus scanner) had the log file open. The error was `OSError (32)`, and the line was lost.
- **Cause (verified):** `FileAppend` opens the file without sharing. As soon as another process holds a handle, even read access with `FILE_SHARE_READ|WRITE`, `FileAppend` fails with 32. There is no retry. `FileGetSize` and `FileExist` still work. (An earlier `OSError (6)` observation could not be reproduced; its cause is assumed to be a stale `A_LastError`.)
- **Wrong:** `FileAppend` for files that other processes may read; discarding a line on error, or retrying in a blocking loop.
- **Right:** `FileOpen(path, "a", "UTF-8-RAW")` without `-rwd` flags (shares read and write). On sharing errors (5, 32, 33), leave the operation at the head of the queue and retry via timer, so the order is kept and the message loop runs between attempts. After 3 s reply `busy` and count the lost line. One operation per file, so a retry never writes the other file twice.
- **Status:** verified (before the fix 3 of 3 runs red, 30 to 40 of 120 lines per source; after the fix 6 of 6 green, `test_no_log_line_is_lost_while_other_processes_hold_the_files`)
- **Source:** `src/storage/LogSink.ahk` (`AppendTo`), `src/storage/WriteQueue.ahk` (`RunOne`)

### Reference cycle via `ObjBindMethod(this, ...)` in a field keeps closed connections alive

- **Problem:** The supervisor grew by about 83 KB per client connection (400 connections: 25 to 58 MB) while the handle count stayed constant. `this._pollFn := ObjBindMethod(this, "Pump")` is a cycle (object → bound function → object), so a closed connection with its buffers is never released.

- **Right:** On close, clear the fields after the timer is switched off with `SetTimer(fn, 0)` (which needs the same function object): `this._pollFn := ""`, `this._notifyFn := ""`. Afterwards the memory stayed flat over 800 connections (17.47 to 17.49 MB). ### Log writes: batch the operations; one operation per timer run is too slow

### Heartbeat: after a standstill of the supervisor all children look hung

### `CreateProcessW` with redirected handles instead of `Run`

- **Problem:** `Run()` starts a process without a usable stderr. Load errors, the messages of `Role.Console` and the last words before a crash were lost; the supervisor only saw the exit code.
- **Right:** Start the child with `CreateProcessW` via `DllCall`:
  - `CreatePipe` with a `SECURITY_ATTRIBUTES` (24 bytes, `bInheritHandle` at offset 16 = 1), then `SetHandleInformation(hRead, HANDLE_FLAG_INHERIT, 0)`: only the write end is inherited. Use a large pipe buffer (256 KB), or the child blocks while the supervisor reads only every 200 ms.
  - `STARTUPINFOEXW` (112 bytes on 64 bit): `cb` at offset 0, `dwFlags` at 60 (`STARTF_USESHOWWINDOW | STARTF_USESTDHANDLES`), `wShowWindow` at 64 (`SW_HIDE` = 0), `hStdInput` at 80, `hStdOutput` at 88, `hStdError` at 96, `lpAttributeList` at 104. `PROCESS_INFORMATION` (24 bytes): `hProcess` at 0, `hThread` at 8, `dwProcessId` at 16.
  - Inherit only the needed handles: `InitializeProcThreadAttributeList`, `UpdateProcThreadAttribute` with `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` (0x20002), `EXTENDED_STARTUPINFO_PRESENT` (0x80000) in the flags. Without the list the child inherits every inheritable handle of the supervisor.
  - The command line must be a writable `Buffer` (`StrPut`), because `CreateProcessW` may write into it.
  - Afterwards close `hWrite`, the NUL handle and the thread handle in the supervisor, or EOF never arrives.
  - Read without blocking: `PeekNamedPipe` for the available bytes, then `ReadFile` for exactly that many. Split lines at byte `0x0A` and only then decode UTF-8 (a character can be split across reads).
- **Pitfalls:** `NumPut("ptr", buffer, ...)` with a `Buffer` object throws "Invalid parameter(s)"; pass `buffer.Ptr`. `StrGet(address, length, "UTF-8")` takes the length in bytes.
- **Status:** verified (`tests/ahk/child_launcher.test.ahk`: stdout, stderr, NUL as stdin, exit code, 40 starts without handle growth; `tests/fault/test_diagnose.py`: 50 restarts, supervisor handles constant). Not checked: that a child really inherits no other handle (no simple way to read the handle table of another process).
- **Source:** `src/supervisor/ChildLauncher.ahk`, `src/supervisor/ChildPipe.ahk`

### Read the header of a JSON frame with one regex; check the payload only for balance

- **Problem:** The hub parsed every frame completely (220 ms for 109,232 characters), but it only needs `to` and must replace `from`.
- **Wrong:** Reading only the start and appending the rest unchecked: a second `"from"` after the payload could then be preferred by a parser ("last key wins"), and the sender would be forged.
- **Right:** One `RegExMatch` on the text in exactly the form of `Message.Serialize` (fixed field order, no whitespace). It captures the payload as a balanced object with PCRE recursion and requires the frame to end there: `(?<obj>\{(?:[^{}"]++|"(?:[^"\\]++|\\.)*+"|(?&obj))*+\})\}\z`. Possessive quantifiers prevent backtracking. If nothing matches, the caller takes the full parse path. Set the regex in `try`, because compilation errors throw. Cost: 1.3 ms for 109,232 characters.
- **Status:** verified (`tests/ahk/message.test.ahk`, cases `ParseHead`/`WithFrom`; a frame with text behind the payload is rejected). Very deep nesting (PCRE recursion limit): not checked.
- **Source:** `src/core/ipc/Message.ahk`, `src/supervisor/Hub.ahk`

### Close discards the send queue: wait until the queue is flushed

- **Problem:** A role sent `sys.bye` and then called `Peer.Close()` and `ExitApp`. `Close` cancels a running write and empties the queue. Frames that did not fit into the pipe (64 KiB, hub not reading at that moment) were lost, including `sys.bye`. Reproduced with a hub that does not read for 0.6 s: 572 of 800 pongs arrived, no `sys.bye`.
- **Wrong:** `Send(...)` followed by `Close()`, assuming the frame is written. `SendFrame` returns `true` as soon as the frame is in the queue. Also wrong: `FlushFileBuffers` on the pipe, which waits without deadline if the reader stands still.
- **Right:** `PipeConnection.CloseWhenFlushed(timeoutMs, onDone)`: no new frames; a timer (10 ms) keeps writing the queue; closing happens when the queue is empty or at the deadline; `onDone(flushed)` runs exactly once, from the timer. `Peer.CloseWhenFlushed` first detaches `OnClose`, so the end does not start a reconnect. The role calls `ExitApp` in the callback and sets an emergency timer (deadline + 1 s).
- **Status:** verified (`tests/integration/test_pipe.py::test_frames_queued_when_the_connection_is_ended_reach_a_late_reader`, `tests/integration/test_role.py::test_frames_queued_at_shutdown_and_the_bye_reach_a_hub_that_reads_late`). ### A re-entry lock makes "pump first" ineffective

- **Problem:** The supervisor calls `hub.Pump()` first, so that an unread `sys.bye` is read before the end of the process is judged. If the tick interrupts a `Pump` of the same connection (woken by the wake-up call, running longer than 15 ms), the lock only sets "again" and returns. The `sys.bye` stays unread and the end is judged `clean: false`.
- **Wrong:** Relying on a call to `Pump()` "reading everything now". With the lock it only means "it will be read, in this or another thread".
- **Right:** Wait for a state, not for an event: judge a terminated process only when its connection has been read to the end (`Hub.HasLink` false), or after a grace period (500 ms). During this time the child counts neither as hanging nor as killed.
- **Status:** verified (unit test `Tick: an exit is not judged while another pump still reads the connection of the child` in `tests/ahk/supervisor_tick.test.ahk`). That this race happened in the real supervisor: assumed.
- **Source:** `src/supervisor/Children.ahk` (`_ExitReadable`, `Terminate`, `MarkHung`)

### A write error to a departed peer must not discard its unread frames

- **Problem:** A child writes `sys.bye` and ends itself. Before the hub reads that frame, the hub writes to the child (an event of a topic it subscribed to). `WriteFile` fails with 232 ("pipe is being closed"); `SendFrame` then called `_Fail` and `_Teardown`, which discarded the unread incoming bytes, including `sys.bye`.

### A router must know which requests are open

### Deadlines via `SetTimer` do not survive a standstill: check them in the tick

- **Problem:** A deadline set with `SetTimer(fn, -ms)` runs on wall-clock time. After a standstill (frozen, standby) the timer is due at once and may run before the tick that notices the standstill. A second trap with the role entries: a relative `#Include` is relative to the folder of the file that contains it, not to the main script, so a copy of an entry script in another folder has to make the paths absolute (`tools/measure_r3.py`, `rewrite_entry`).
- **Wrong:** An element base class that includes only `Errors.ahk` while the element files use `Lang()`; a copy of `src/entry/engine.ahk` in a temporary folder with the includes unchanged.
- **Right:** `elements/base/AhfElement.ahk` includes `core/Lang.ahk`, so every role with element classes has it. Copies of entry scripts get absolute include paths. The file-level code of an element (`ElementRegistry.Register`) runs when the file is included, also when a class file includes another class file, so such an include registers the class in every role that includes the first file (F-0081).
- **Status:** verified (WI-0047-PREP: the warning dialog before the change, the measurement and `tests/test_element_includes.py` after it)
- **Source:** `src/elements/base/AhfElement.ahk`, `tools/measure_r3.py`

### A timer thread can run between "check" and "use" of a shared Map entry

- **Problem:** AutoHotkey runs a timer or a message handler between two lines of another thread unless `Critical` is on. `if (!m.Has(k)) ...` followed by `m[k]` on the next line is not atomic: when the timer deletes `k` in between, `m[k]` throws `UnsetItemError`. In storage this was a log line that vanished without a count (F-0088: `_LogToFile` against `_FinishLogBundle`). The error is easy to miss: a handler that throws is only a log line.
- **Wrong:** `if (!this.logBuffers.Has(f)) this.logBuffers[f] := Map(...)` and then `buf := this.logBuffers[f]`; and a flag, a check and a `Delete` of the same entry in another thread without `Critical`.
- **Right:** Read once (`buf := m.Get(k, "")`, create if not an object) and run every change of the shared state (flag, check, removal, scheduling) in one `Critical` section in both threads (`prev := Critical("On")` ... `finally Critical(prev)`).
- **Status:** verified (burst test red about 1 in 3 under load before, 0 of 30 after; `tests/ahk/storage_logbuf.test.ahk` red before, green after)
- **Source:** `src/storage/Storage.ahk` (`_LogToFile`, `_FinishLogBundle`), `doc/OPEN-ITEMS.md` F-0088

### `FlowRun.probe` reads the files when it is called: the next run clears them

- **Problem:** A test that runs several flows one after the other and calls `run.probe("x")` at the end reads the probe files of the LAST run (`flows.begin` clears `global_probe*` before every run), or `None`, and a test of the first flow fails for no visible reason.
- **Wrong:** `runs = [flows.run(i) for i in ids]` and then `runs[0].probe("x")`.
- **Right:** read the probes right after the run, before the next one starts (`tests/integration/test_core_a_elements.py::run_all` stores them in `run.seen`). A run that ended with an exception has no probe: `probe` then waits for its timeout, so read it only for a flow that finished.
- **Status:** verified (WI-0052)
- **Source:** `tests/support/flowrun.py`, `tests/integration/test_core_a_elements.py`

### `psutil.cpu_percent(interval=None)` keeps its reference point per thread

- **Problem:** The load sampler (WI-0059) primed `psutil.cpu_percent(interval=None)` in the main thread and read it in its own thread one second later: the first value was always `0.0`.
- **Wrong:** Priming in one thread and reading in another, or relying on the first call of a new thread.
- **Right:** Compute the system load from two `psutil.cpu_times()` readings (busy = total minus idle, both summed over the cores), which has no hidden state (`tests/support/loadsampler.py`).
- **Status:** verified (by hand: main thread `21.0`, a new thread `0.0` after one second; psutil 6.1.1)

### CPU of a process tree including the processes that already ended: a job object

- **Problem:** A psutil walk over the children only sees processes that are alive at the moment of a sample. Test processes that live shorter than one second, and the xdist workers that end before `pytest_sessionfinish`, then count as external load.
- **Right:** The controller assigns itself to a job object of its own (`CreateJobObjectW`, `AssignProcessToJobObject(GetCurrentProcess())`); every process started below it is in the job, and `QueryInformationJobObject(JobObjectBasicAccountingInformation)` returns the user and kernel time of all processes that were ever in it, plus the number of active ones. Set `argtypes`/`restype` for every call (64-bit handles, see above). Nested jobs need Windows 8 or later; the fallback is the psutil walk (history field `load.ownTree`: `job` or `psutil`). The job gets no limit at all (no `SetInformationJobObject`): no `KILL_ON_JOB_CLOSE`, so the end of the controller kills nothing.
- **Limits:** (1) A process that leaves the job is missing from the sum and counts as external load. With our job (no `JOB_OBJECT_LIMIT_BREAKAWAY_OK`) a child cannot break away: `CreateProcess` with `CREATE_BREAKAWAY_FROM_JOB` fails with error 5 (access denied), so a program that insists on breaking away does not start inside a test run at all. Nothing in the repository uses that flag. (2) A process that a test causes but that is not started below the controller (a service, a COM server, a program started through the shell of the desktop) is not in the job either and counts as external.
- **Status:** verified: own vs external (`tests/test_runtool_runs.py::test_external_load_shows_in_the_figures_of_the_test`), no limit flags and refused breakaway (`tests/test_runtool_runs.py::test_the_job_object_only_counts`), fallback (`tests/test_load_history.py::test_without_a_job_the_sampler_falls_back_to_psutil`). Limit (2) is assumed, not tested.
- **Source:** `tests/support/loadsampler.py`
