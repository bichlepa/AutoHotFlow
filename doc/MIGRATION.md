# Migration v1 → v2: deliberate behavior changes

Updated continuously. Silent behavior changes are not allowed: everything that is intentionally different in v2 is recorded here.

| ID | Area | v1 | v2 | Reason | Status |
|---|---|---|---|---|---|
| M-0001 | Crash of the engine | A crash of the one process ends everything, running instances are gone | The supervisor restarts the engine, running instances are gone, UIs stay connected and resynchronize | Architecture (processes) | planned |
| M-0002 | Dialog elements (`Message_Box`, `Input_Box`, `Select_file`, `Confirmation_Dialog` etc.) | Dialog opens from the execution thread | Dialog opens from a worker process. Window order/focus may differ slightly. | Engine must not block | planned |
| M-0003 | Hotkey trigger `Disable` | `hotkey, <key>, off` without window context, a context-bound hotkey can stay active | same `HotIf` context as when it was activated | Bug fix | planned |

| M-0005 | Logs | several threads write under a global lock | `storage` is the only writer. File names and format unchanged. | Architecture | planned |
| M-0006 | Variables `global`/`static` | direct file access under lock | Engine keeps a working copy in memory, `storage` reads and writes asynchronously (write-behind).
