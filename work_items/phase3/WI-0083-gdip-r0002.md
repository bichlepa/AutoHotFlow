# WI-0083 GDI+ wrapper and the R0002 measurement

Size: M · Depends on: – · Blocks: WI-0085

## Goal

AutoHotkey v2 draws with GDI+ through a small wrapper of our own (E0085), and a measurement settles risk R0002 before any code relies on it: does a frame of a flow with 300 elements stay below 16 ms on average (ARCHITECTURE 2.1, REQ-PRF-060)? If not, the owner decides how to go on before WI-0085 starts. May start before WI-0082 (only new files).

## Read first

`AGENTS.md`; `doc/ARCHITECTURE.md` 2.1, 8, 10 (R0002); `doc/CONVENTIONS.md`; `doc/MEASUREMENTS.md` ("Important: one machine", "Method"); the v1 drawing `v1/Source_Draw/GDIp/GDIp.ahk` (which GDI+ calls v1 makes per element and connection) and the sizes in `v1/Source_Common/Other/Design.ahk`; the GDI+ flat API of Microsoft (`GdiplusStartup`, `GdipCreateFromHDC`, `GdipDrawString`, `GdipCreateBitmapFromFile`, ...).

## Tasks

1. **Wrapper** `src/editor/render/Gdip.ahk` (E0085): `GdiplusStartup` once per process and `GdiplusShutdown` at the end; a DIB section with its memory DC as the target (also without a window); graphics from a DC; smoothing and text rendering hints; solid brush; pen (width, color); fill and draw of rectangle, rounded rectangle (path), polygon and lines; text with font family, size, style and string format (horizontal and vertical centering, clipping to a box, ellipsis); image from a file (`.ico`, `.png`) drawn scaled and with alpha; the copy of a DC to a window (`BitBlt`). Every object that is created has its delete; a GDI+ status other than `Ok` throws `AhfError` with the name of the status. One class per file (CONVENTIONS 1): split into small classes if needed (`Gdip`, `GdipBitmap`, ...).
2. **Unit test** `tests/ahk/gdip.test.ahk`: draw into a 200×100 bitmap without a window and read pixels back: the color of a filled rectangle, text changes pixels only inside its box, an icon file of `src/elements/Default/Icons/` loads and is drawn; 1000 frames leave the number of GDI objects of the process unchanged (`GetGuiResources`).
3. **Measurement** `tests/ahk/helpers/render_bench.ahk` and `tools/measure_render.py`: a synthetic scene that draws the way v1 draws (per element fill, border, icon, name; per connection five line segments, a third of them with a label `yes`/`no`; 30 elements tinted as running; the grid dots). 300 elements of the four kinds with names of 10 to 30 characters and an icon, 350 connections. Cases: 1920×1080 and 3840×2160; the whole flow visible (zoomed out) and zoom 1 (only a part visible, the rest culled); anti-aliasing on and off. 10 frames warm-up, then 100 frames; mean, median and p95 per case, and the time of the `BitBlt` to a window of that size (a `gui` variant, run by the owner, or skipped). The run is serial and alone (as the `idle` tier).
4. **If the mean at 1920×1080 with the whole flow visible is above 16 ms:** measure the obvious remedies too (the names drawn once into a cached bitmap per element; a static layer of the elements and connections with only the states drawn on top; no text below a size of a few pixels) and stop: the numbers and the options, including the render process of ARCHITECTURE 2.1, go to the owner. WI-0085 waits for the decision.
5. **Documents:** the results as an MS entry in `doc/MEASUREMENTS.md`; ARCHITECTURE 2.1 and 10 (R0002) say what was measured; REQ-PRF-060 gets the frame part as evidence when it is green. VS Code task `Tool: render measurement (R0002)`. Group table entries for the new files.

## Acceptance criteria

- The unit test is green, `python tools/arch_check.py` is green.
- The measurement is recorded with its status (one machine, run alone) and R0002 has its answer, or the owner's decision is pending with the numbers in the result.

## Not part of this

The real geometry of v1 (WI-0084; the bench uses simple five-segment lines), the renderer and its look (WI-0085).
